# РАЗДЕЛ 1. РОЛЬ: СМЕТЧИК (КЛИЕНТ)

**Кто это:** Основной пользователь. Просит счета, помощь и управляет своими данными.  
**Точка входа:** Кнопка `/start`.

## 1.1. Сценарий: Регистрация нового сметчика

**Предусловие:** Пользователь впервые зашел в бот.

### Шаг 1. Приветствие и Запрос телефона

**Бот (Сообщение):**
```
👋 Здравствуйте! Я — АЙТАТ-Диспетчер.
Помогу вам получить счета, связаться с техподдержкой или продлить подписку.
Для начала работы мне нужно подтвердить ваш номер телефона.
Нажмите кнопку ниже, чтобы отправить контакт.
```

**Бот (Клавиатура Reply):**
- `[📱 Поделиться телефоном]` (request_contact=True)

**Действие:** Пользователь нажимает кнопку. Telegram запрашивает подтверждение.

**Логика системы:**
- Бот проверяет: если контакт прислан не кнопкой — просит нажать кнопку.
- Бот отправляет запрос `check_register` в 1С.
- Если ответ `active` — сразу пускаем в меню (пропуск шагов 2-5).
- Если ответ `not_found` — идем к Шагу 2.

### Шаг 2. Ввод Имени и Фамилии

**Бот:** «Спасибо! Как к вам обращаться? (Фамилия Имя)»  
**Пользователь:** «Смирнова Мария»  
**Логика:** Бот сохраняет `full_name` в память (FSM).

### Шаг 3. Ввод ИНН Организации

**Бот:** «Укажите ИНН организации (10/12 цифр).»  
**Пользователь:** «1655060636»  
**Логика:** Бот валидирует (только цифры, длина). Сохраняет `inn`.

### Шаг 4. Ввод ключа ГРАНД-Сметы

**Бот:** «Укажите номер ключа (Пример: MG555666).»  
**Пользователь:** «MG123456»

**Логика (API Запрос):**
- Бот шлет запрос проверки ключа в 1С.
- **Вариант А (ОК):** Ключ свободен. Идем дальше.
- **Вариант Б (Конфликт):** 1С возвращает ошибку «Ключ занят».
  - **Бот:** «⚠️ Этот ключ зарегистрирован за другим пользователем. Мы создали заявку на проверку.»
  - Бот помечает ключ флагом `conflict`, но пускает пользователя дальше.

### Шаг 5. Отправка и Ожидание

**Бот:**
```
✅ Данные приняты!
Заявка отправлена администратору. Ожидайте уведомления.
```

**Логика:** Бот отправляет полный пакет данных в 1С методом `register`. Бот переходит в режим «Ждуна» (блокирует меню).

### Шаг 6. Финал (Webhook от 1С)

**Триггер:** Админ в CRM нажал «Подтвердить».

**Бот (Push):**
```
🎉 Регистрация подтверждена!
Ваш менеджер: Петрова Анна.
Режим работы: 08:00–17:00.
```

**Бот:** Открывает Главное меню.

## 1.2. Сценарий: Получить счет

**Предусловие:** Пользователь в Главном меню.

### Шаг 1. Выбор Организации

**Пользователь:** Жмет `[📄 Получить счет]`.

**Логика:** Бот делает запрос `get_assets` в 1С (чтобы получить свежий список фирм).

**Бот:** «На кого выставляем счет?»
- `[ООО "Ромашка"]`
- `[ИП Иванов]`
- `[➕ Добавить новый ИНН]`
- `[Пропустить]`

### Шаг 2. Выбор ключа

**Бот:** «Для какого ключа услуга?»
- `[✅ MG123456]` (Мультивыбор)
- `[➕ Указать другой]`
- `[Готово]`

### Шаг 3. Описание и Доставка

**Бот:** «Напишите, что включить в счет?»  
**Пользователь:** «Индексы февраль»  
**Бот:** «Куда отправить?» → Выбор `[Telegram]` или `[Email]`.

### Шаг 4. Финализация (Бот-Диспетчер)

**Логика (Внутри Бота):**

**Определение менеджера:**
- Если выбран ИНН — Бот смотрит в своем кэше: «Кто закреплен за ООО Ромашка?». → Анна.
- Если ИНН нет — Бот берет «Основного менеджера» пользователя.

**Создание Тикета:** Бот создает тикет #105 в своей БД.

**Уведомление:** Бот отправляет сообщение напрямую в чат Анне: «🔔 Новый запрос счета #105!».

**Таймер:** Бот запускает отсчет 10 минут.

**Бот (Клиенту):**
```
✅ Заявка #105 принята!
Менеджер Анна уже получила уведомление.
Ожидайте файл.
```

> Если сейчас нерабочее время по календарю бота — он пишет: «Офис закрыт, Анна ответит утром» и не запускает таймер эскалации до 08:00.

### Шаг 5. Получение счета

**Менеджер:** Присылает PDF в чат с ботом.  
**Бот:** Пересылает PDF клиенту.

```
📄 Счет №555 от 30.01
Сообщение от Анны: "Все готово!"
```

## 1.3. Сценарий: Техподдержка (Dispatcher Mode)

**Предусловие:** Пользователь жмет `[🛠 Техподдержка]`.

### Шаг 1. Проверка прав (Бот-Логика)

**Логика:** Бот проверяет флаг `is_support_active` (полученный ранее от 1С).

- **Активна:** Идем к Шагу 2.
- **Истекла:**
  - **Бот:** «⚠️ Срок договора истек. Передать заявку менеджеру на продление?»
  - `[Да, продлить]` → Создается тикет типа «Продажа» на менеджера (как в сценарии Счет).
  - `[Отмена]` → Выход.

### Шаг 2. Сбор проблемы

**Бот:** «Опишите проблему (текст/фото/голос).»  
**Пользователь:** Пишет текст.  
**Бот:** «С каким ключом проблема?» → Выбор ключа из кнопок.

### Шаг 3. Маршрутизация по времени (Календарь Бота)

Бот смотрит на часы и свой календарь:

**Вариант А (Рабочее время):**
- Тикет отправляется в группу «Техподдержка».
- **Клиенту:** «Инженер подключится в течение 15 минут.»

**Вариант Б (Продленное время 17-20):**
- Бот смотрит график дежурств. Сегодня дежурный: Алексей.
- Тикет отправляется лично Алексею.
- Запускается таймер эскалации (10 мин).
- **Клиенту:** «Сейчас работает дежурный инженер.»

**Вариант В (Ночь):**
- Тикет сохраняется в очередь «Утро».
- **Клиенту:** «Офис закрыт. Ответим с 08:00 МСК.»

### Шаг 4. Диалог

**Сотрудник:** Пишет ответ.  
**Бот:** Пересылает сообщение клиенту.

```
👨‍💻 Алексей (ТП):
Попробуйте нажать эту кнопку...
```

**Клиент:** Отвечает Reply-ем.  
**Бот:** Пересылает сотруднику.

## 1.4. Сценарий: Профиль (Мои данные)

**Предусловие:** Пользователь жмет `[👤 Мои данные]`.

### Шаг 1. Просмотр

**Бот:** Выводит карточку:

```
Имя: Смирнова Мария
Телефон: +7999...
Организации:
  ООО Ромашка (1655...)
Ключи:
  MG123456
Подписка на новости: ✅ ВКЛ
```

**Кнопки:**
- `[➕ Добавить ИНН]`
- `[➕ Добавить Ключ]`
- `[🔄 Сменить телефон]`
- `[🔔 Рассылка Вкл/Выкл]`

### Шаг 2. Добавление данных

**Добавить ИНН:**
- Пользователь вводит цифры.
- Бот проверяет формат.
- Бот шлет запрос в 1С `update_assets`.
- Успех → ИНН появляется в списке.

**Добавить Ключ:**
- Пользователь вводит MG....
- Бот шлет запрос `check_key` в 1С.
- Если 1С отвечает `conflict` → Бот блокирует и создает заявку Админу.
- Если `available` → Добавляет ключ.

### Шаг 3. Смена телефона

**Пользователь:** Жмет `[🔄 Сменить телефон]`.  
**Бот:** «Смена номера требует проверки. Введите новый номер.»  
**Пользователь:** Вводит номер.  
**Логика:** Бот создает тикет для Администратора. Данные в профиле не меняются, пока Админ не подтвердит.
## 1.5. Сценарий: Техподдержка (Обращение в ТП)

**Предусловие:** Пользователь находится в Главном меню и нажимает кнопку `[🛠 Техподдержка]`.

### Шаг 1. Проверка прав (API запрос)

**Скрытый шаг.** В момент нажатия бот делает запрос `GET /api/v1/user/status` в 1С.

**Ветвление:**

**Подписка Активна** (`is_support_active: true`):
- Бот переходит к Шагу 2.

**Подписка Истекла** (`false`):
- **Бот:**
  ```
  ⚠️ Срок действия договора истек.
  К сожалению, техническая поддержка доступна только при активной подписке.
  Мы можем передать ваш запрос менеджеру для продления договора.
  ```
- **Кнопки:** `[Передать менеджеру]` / `[Отмена]`
- **Логика:** Если выбрано «Передать менеджеру», Бот запускает создание тикета с типом `renewal` (аналогично сценарию «Получить счет»).

### Шаг 2. Описание проблемы

**Бот:**
```
Шаг 1/2. Опишите вашу проблему.
Примеры:
— "Ошибка при запуске: не найден ключ"
— "Как загрузить индексы?"
Вы можете прислать текст, фото экрана или голосовое сообщение.
```

**Пользователь:** Пишет текст (например: "Ошибка 404 при сохранении") или шлет скриншот.  
**Бот:** Сохраняет данные в памяти.

### Шаг 3. Выбор ключа (Контекст)

**Бот:**
```
Шаг 2/2. С каким ключом возникла проблема?
(Это поможет инженеру быстрее найти решение)
```

**Клавиатура (Inline):** (Данные подтянуты из кэша бота или API)
- `[MG123456]`
- `[MG999888]`
- `[➕ Другой ключ]`
- `[Не знаю / Пропустить]`

**Действие:** Пользователь выбирает ключ.

### Шаг 4. Маршрутизация (Бот-Диспетчер)

Бот формирует тикет и проверяет свой **Глобальный Календарь** (Время МСК):

**Вариант А: Основное рабочее время (Пн-Пт 08:00–17:00)**
- Бот отправляет Тикет в 1С (для лога).
- Бот отправляет уведомление в Telegram-группу Техподдержки (или распределяет на свободных сотрудников, полученных из `GET /system/staff`).
- **Бот (Клиенту):**
  ```
  ✅ Заявка в техподдержку #TP-200 принята.
  Инженер подключится в течение 15 минут.
  Ожидайте ответа здесь.
  ```

**Вариант Б: Продленное время (Пн-Пт 17:00–20:00, Сб 09:00–13:00)**
- Бот определяет текущего Дежурного (по графику в боте).
- Бот шлет уведомление лично Дежурному: «🔥 Срочный тикет #TP-200!».
- **Бот (Клиенту):**
  ```
  ✅ Заявка #TP-200 принята (Дежурный режим).
  Сейчас работает дежурный инженер. Он ответит вам в порядке очереди.
  ```
- **Таймер (Логика Бота):**
  - Бот ждет 10 минут.
  - Если Дежурный не нажал `[Взять в работу]`, Бот шлет ему напоминание.
  - Если еще через 10 минут тишины — Бот шлет уведомление в канал Эскалации (Админу).

**Вариант В: Нерабочее время (Ночь/Воскресенье)**
- Бот сохраняет тикет в статус `Очередь (Ночь)`.
- **Бот (Клиенту):**
  ```
  🌙 Заявка #TP-200 принята.
  Сейчас техподдержка отдыхает. Мы видим ваш запрос и ответим первым делом в рабочее время (с 08:00 МСК).
  ```

### Шаг 5. Диалог

**Сотрудник:** Нажимает `[Взять в работу]`.  
**Сотрудник:** Пишет ответ в бот: «Попробуйте переустановить драйвер...».

**Бот (Клиенту):**
```
👨‍💻 Алексей (ТП):
Попробуйте переустановить драйвер...
```

**Клиент:** Делает Reply: «Помогло, спасибо!».  
**Бот:** Пересылает ответ Алексею.

### Шаг 6. Закрытие

**Сотрудник:** Жмет `[Закрыть вопрос]`.  
**Бот (Клиенту):** «Вопрос закрыт. Если возникнет новая проблема — пишите!»  
**Бот:** Отправляет лог закрытия в 1С (`POST /tickets/log`).

## 1.6. Сценарий: Управление профилем

**Точка входа:** Кнопка `[👤 Мои данные]` в Главном меню.

### Шаг 1. Просмотр данных

**Бот:** Отображает карточку пользователя (данные обновляются через `GET /user/assets` при входе).

```
Имя: Смирнова Мария
Тел: +7999...
Организации: ООО Ромашка (1655...)
Ключи: MG123456
Рассылка: ✅ Вкл
```

**Кнопки:**
- `[➕ Добавить ИНН]`
- `[➕ Добавить ключ]`
- `[🔄 Сменить телефон]`
- `[🔔 Рассылка Вкл/Выкл]`

### Шаг 2. Добавление ИНН

**Пользователь:** Жмет `[➕ Добавить ИНН]`.  
**Бот:** «Введите ИНН».  
**Пользователь:** Вводит цифры.  
**Бот:** Проверяет формат → Отправляет в 1С `POST /user/add_inn`.  
**Результат:** Список обновляется.

### Шаг 3. Добавление Ключа (С проверкой конфликта)

**Пользователь:** Жмет `[➕ Добавить ключ]`.  
**Бот:** «Введите номер ключа».  
**Пользователь:** Вводит MG123....  
**Бот:** Отправляет запрос `POST /assets/check_key`.

- **Ответ 1С `available`:** Бот добавляет ключ и пишет «Успешно».
- **Ответ 1С `conflict`:** Бот пишет: «⚠️ Ключ занят другим пользователем. Создана заявка администратору на проверку». (Создается тикет Админу).

### Шаг 4. Смена телефона

**Пользователь:** Жмет `[🔄 Сменить телефон]`.  
**Бот:** «Смена номера требует ручного подтверждения. Введите новый номер для связи.»  
**Пользователь:** Вводит новый номер.  
**Бот:** Создает тикет для Администратора с типом `Change_Phone`. Пользователю: «Заявка отправлена».
