Сервис диспетчеризации Telegram (HTTP). Методы регистронезависимы.

1. Метод GET /getinfo. Возвращает данную справку по сервису — описание методов и параметров сервиса.

        Пример запроса: http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/getinfo/

2. Метод GET /system/staff. Возвращает список активных сотрудников с учетными записями в мессенджерах. Описание полей элемента массива:
        * user_id - идентификатор пользователя в Telegram (число);
        * name - имя пользователя (наименование из справочника Пользователи);
        * role - роль пользователя (строковое представление перечисления);
        * position - должность для подписи (строка).

        Возвращает объект:
        * status - "ok";
        * staff - массив объектов сотрудников.

        Ошибки: 500 при внутренней ошибке сервера.
        Пример запроса: http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/system/staff/

3. Метод POST /user/register. Регистрирует нового пользователя в системе.
        Принимает JSON с полями:
        * telegram_id - идентификатор пользователя в Telegram (число, обязательное);
        * phone - номер телефона (строка, обязательное);
        * first_name - имя пользователя (строка, необязательное);
        * last_name - фамилия пользователя (строка, необязательное);
        * grand_key - ключ защиты (строка, обязательное).

        Возвращает объект:
        * status - "ok";
        * message - текстовое сообщение;
        * user_id - идентификатор зарегистрированного пользователя;
        * potential_matches - количество потенциальных совпадений по телефону (опционально).

        Ошибки: 400 - неверные параметры, 404 - ключ не найден, 409 - пользователь уже существует, 500 - внутренняя ошибка.
        Пример запроса: POST http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/user/register/
        Пример тела запроса: {"telegram_id": 123456789, "phone": "+79001234567", "first_name": "Иван", "last_name": "Иванов", "grand_key": "00202_12345"}

4. Метод GET /user/assets. Возвращает список активов пользователя (организации и ключи защиты).
        Принимает параметры запроса:
        * telegram_id - идентификатор пользователя в Telegram (число, обязательное).

        Возвращает объект при успехе (пользователь верифицирован):
        * status - "ok";
        * organizations - массив объектов организаций с полями: inn (ИНН), name (наименование);
        * keys - массив строк с номерами ключей защиты.

        Возвращает объект при ошибке (пользователь не верифицирован):
        * status - "error";
        * message - "Пользователь не верифицирован";
        * verification_status - текущий статус верификации пользователя.

        Ошибки: 400 - неверные параметры, 404 - пользователь не найден, 500 - внутренняя ошибка.
        Пример запроса: GET http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/user/assets/?telegram_id=123456789

5. Метод POST /tickets/log. Регистрирует обращение пользователя в периодическом регистре сведений.
        Принимает JSON с полями:
        * ticket_id - идентификатор обращения (строка, обязательное);
        * telegram_id - идентификатор пользователя в Telegram (число, обязательное);
        * type - тип обращения (строка, обязательное, значение из перечисления ай_ТипОбращения);
        * status - статус обращения (строка, обязательное, значение из перечисления ай_СтатусыОбращений);
        * history_link - ссылка на историю чата (строка, необязательное);
        * comment - комментарий сотрудника (строка, необязательное).

        Возвращает объект:
        * status - "ok";
        * message - "Обращение зарегистрировано";
        * ticket_id - идентификатор зарегистрированного обращения.

        Примечание: При статусе "Закрыто" автоматически проставляется дата закрытия обращения.

        Ошибки: 400 - неверные параметры или недопустимые значения type/status, 404 - пользователь не найден, 500 - внутренняя ошибка.
        Пример запроса: POST http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/tickets/log/
        Пример тела запроса: {"ticket_id": "TG_12345", "telegram_id": 123456789, "type": "Техподдержка", "status": "Новое", "history_link": "https://t.me/c/123/456", "comment": "Клиент запросил помощь"}

6. Метод POST /assets/check_key. Проверяет, доступен ли ключ защиты для использования или занят другим клиентом.
        Принимает JSON с полями:
        * grand_key - номер ключа защиты (строка, обязательное);
        * telegram_id - идентификатор пользователя в Telegram (число, обязательное).

        Возвращает объект при доступном ключе:
        * status - "available" (ключ свободен или уже принадлежит текущему пользователю).

        Возвращает объект при конфликте:
        * status - "conflict";
        * owner - имя и маскированный телефон владельца ключа (формат: "Имя Фамилия +7912-XXX-XX-89").

        Примечание: Телефон маскируется, оставляя первые 4 и последние 2 цифры.

        Ошибки: 400 - неверные параметры, 500 - внутренняя ошибка.
        Пример запроса: POST http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/assets/check_key/
        Пример тела запроса: {"grand_key": "MG123456", "telegram_id": 123456789}
