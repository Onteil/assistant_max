# РАЗДЕЛ 3. РОЛЬ: АДМИНИСТРАТОР

**Кто это:** Суперпользователь с полным доступом к управлению ботом.  
**Точка входа:** Кнопка `[🔐 Админ-панель]` в главном меню (доступна, если `is_admin=True`).
## 3.1. Управление сотрудниками

**Точка входа:** `[🔐 Админ-панель]` → `[👥 Сотрудники]`.

### Сценарий: Добавление нового сотрудника

1. **Админ:** Нажимает `[➕ Добавить сотрудника]`.
2. **Бот:** «Пришлите Telegram ID сотрудника или перешлите любое его сообщение мне в чат».
3. **Админ:** Пересылает сообщение от будущего сотрудника.
4. **Бот (Валидация):** Проверяет ID, не зарегистрирован ли он уже.
5. **Бот:** «Выберите роль сотрудника:»
   - `[Менеджер]` `[Техподдержка]` `[Администратор]`
6. **Админ:** Выбирает роль (например, Менеджер).
7. **Бот:** «Введите подпись сотрудника (будет видна клиентам).»
   - Пример: *Маркова Виктория, специалист поддержки.*
8. **Админ:** Вводит текст подписи.
9. **Бот:** Сохраняет сотрудника, шлет ему уведомление о доступе.

```
✅ Сотрудник добавлен!
ID: 1234567 | Роль: Менеджер
```
### Сценарий: Редактирование и Деактивация

1. **Админ:** Нажимает `[📋 Список сотрудников]`.
2. **Бот:** Выводит список имен.
3. **Админ:** Выбирает сотрудника `[Маркова Виктория]`.
4. **Бот:** Показывает карточку и кнопки:
   - `[✏️ Изменить подпись]` — ввод нового текста.
   - `[🎭 Сменить роль]` — выбор новой роли.
   - `[🚫 Деактивировать]` — отключение доступа.

**Деактивация:**
- При нажатии Бот спрашивает подтверждение.
- При согласии: Статус сотрудника меняется на `inactive`. Его активные тикеты переходят в статус «Новое» (в общую очередь).
### Сценарий: Настройка резервов (Цепочка эскалации)

1. **Админ:** В карточке сотрудника жмет `[🛡 Настроить резервы]`.
2. **Бот:**
   ```
   Резервы для: Иванов Иван
   Не назначен
   Не назначен
   ```
3. **Админ:** Жмет `[Выбрать Резерв 1]` → выбирает сотрудника из списка.
4. **Результат:** Бот сохраняет связку. Теперь таймер «10 минут» будет перекидывать заявки на выбранного резервиста.
### Сценарий: Переназначение (Трансфер)

**Ситуация:** Менеджер заболел, нужно раскидать его задачи.

**Вариант А: Один тикет**
1. **Админ:** В просмотре тикета жмет `[🔄 Переназначить]`.
2. **Админ:** Выбирает нового сотрудника.
3. **Бот:** Меняет ответственного, шлет уведомления.

**Вариант Б: Все клиенты менеджера**
1. **Админ:** В карточке менеджера жмет `[👤 Передать всех клиентов]`.
2. **Админ:** Выбирает получателя.
3. **Бот:** Отправляет API-запрос в 1С на обновление поля «Закрепленный менеджер» для всех связанных ИНН.
## 3.2. Операционная деятельность

### Сценарий: Подтверждение регистрации сметчика

**Срабатывает,** когда новый пользователь проходит регистрацию.

**Уведомление:** Бот присылает Админу сообщение:

```
🆕 Заявка на регистрацию
ФИО: Смирнова Мария
Тел: +7999...
ИНН: 1655... (ООО Ромашка)
Ключ: MG123456
```

**Действия:**
- `[✅ Подтвердить]` — Бот шлет API-запрос в 1С `approve_user`. Сметчику улетает Push о доступе.
- `[❌ Отклонить]` — Бот просит ввести причину отказа. Шлет API-запрос `reject_user`. Сметчик получает отказ.
- `[🔍 На проверку]` — Оставляет заявку в списке «Ожидающих» для ручного разбора.
### Сценарий: Глобальная рассылка

**Точка входа:** `[🔐 Админ-панель]` → `[📢 Рассылка]`.

1. **Создание:** Админ присылает пост (текст/фото).
2. **Таргетинг:**
   - `[Всем]`
   - `[С активной подпиской]`
   - `[Только согласившимся на маркетинг]`
3. **Превью:** Бот показывает черновик.
4. **Запуск:** Админ жмет `[🚀 Запустить]`.
5. **Финал:** Бот присылает отчет (Отправлено / Ошибок).
### Сценарий: Обработка конфликта ключа

**Ситуация:** Сметчик ввел ключ, который уже занят.

**Уведомление:**
```
⚠️ КОНФЛИКТ КЛЮЧА
Новый юзер: Петров (+7999...)
Ввел ключ: MG555
Старый владелец: Иванов (+7888...)
```

**Действия:**
- `[✅ Передать Петрову]` — Ключ отвязывается от Иванова и привязывается к Петрову. Оба получают уведомления.
- `[❌ Отказать Петрову]` — Новый юзер получает ошибку.
- `[📞 Связаться]` — Показывает контакты обоих для звонка.
### Сценарий: Реакция на эскалацию (SOS)

**Ситуация:** Дежурный или менеджер пропустил все таймеры (20 минут тишины).

**Уведомление:**
```
🔥 ЭСКАЛАЦИЯ! Заявка #200 висит 20 мин!
Тип: ТП (Дежурство)
```

**Быстрые действия:**
- `[➡️ Переназначить]` — Выбор другого сотрудника.
- `[🙋‍♂️ Взять на себя]` — Админ входит в режим диалога с клиентом.
- `[📞 Позвонить дежурному]` — Вывод контакта.
## 3.3. Управление календарем и настройками

**Точка входа:** `[🔐 Админ-панель]` → `[📅 График работы]`.

### Сценарий: Просмотр (Дашборд)

**Бот:** Показывает текущий статус (Рабочее/Нерабочее), базовый график и список активных исключений на ближайшие дни.

**Кнопки:** `[📅 На неделю]`, `[📋 Список правил]`, `[🗑 Очистить период]`.
### Сценарий: Настройка (Текстовые команды)

Админ отправляет команды в чат для гибкой настройки:

**Изменение рабочего времени:**
- **Ввод:** `31 января рабочее время с 9 до 15`
- **Результат:** 31.01 офис закроется в 15:00.

**Установка дежурства:**
- **Ввод:** `31 января продленное рабочее время с 17 до 20`
- **Результат:** В это время заявки пойдут Дежурному ТП.

**Выходные (Диапазон):**
- **Ввод:** `с 1 по 5 февраля нерабочее время`
- **Результат:** Полный выходной на 5 дней.

**Очистка:**
- **Ввод:** `Удалить правило 1` (по номеру из списка).
- **Кнопка:** `[🗑 Очистить период]` → Ввод дат → Полный сброс к базовому графику.
### Сценарий: Системные настройки

**Точка входа:** `[⚙️ Настройки бота]`.

- **Технический режим:** Переключатель `[ВКЛ/ВЫКЛ]`. Если включен — бот отвечает всем (кроме админов): «Ведутся технические работы».
- **Контакты:** Изменение телефона поддержки, который показывается при ошибках.
## 3.4. Аналитика

**Точка входа:** `[🔐 Админ-панель]` → `[📊 Статистика]`.

**Бот:** Формирует отчет за сегодня/неделю:

- Количество новых заявок (Счета / ТП / Продления).
- Среднее время реакции (SLA) по отделу.
- Список «зависших» тикетов (статус «Новое» > 15 мин).
- NPS: Средняя оценка и кол-во проголосовавших.
