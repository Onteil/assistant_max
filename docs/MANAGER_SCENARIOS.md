# РАЗДЕЛ 2. РОЛЬ: СОТРУДНИК (МЕНЕДЖЕР / ТЕХПОДДЕРЖКА)

**Кто это:** Внутренний пользователь, обрабатывающий заявки.  
**Точка входа:** Специальное меню после назначения роли Администратором.

## 2.1. Сценарий: Инициализация и Меню

**Предусловие:** Администратор добавил сотрудника в систему.

### Шаг 1. Получение доступа

**Бот (Push):**
```
🔐 Вам открыт доступ к панели сотрудника.
Роль: Менеджер
Используйте /start для обновления интерфейса.
```

### Шаг 2. Рабочее меню

**Сотрудник:** Вводит `/start`.

**Бот:** Показывает клавиатуру сотрудника:
- `[📥 Активные тикеты]` — список того, что уже взято в работу.
- `[🗄 Архив обращений]` — поиск по закрытым.
- `[⚙️ Настройки]` — просмотр своей подписи.
- `[🔐 Админ-панель]` — (только если есть права админа).
## 2.2. Сценарий: Обработка нового обращения

**Предусловие:** Клиент создал заявку, бот определил маршрут.

### Шаг 1. Уведомление

**Бот:** Присылает сообщение в чат сотруднику:

```
🔔 Новое обращение #105 (Счет)
Клиент: ООО Ромашка (Иванов И.)
Тема: Индексы февраль
⏳ Таймер: 10:00
```

**Кнопки:** `[Взять в работу]`

### Шаг 2. Взятие в работу

**Сотрудник:** Нажимает `[Взять в работу]`.

**Логика Бота:**
- Останавливает таймер эскалации (резерв не будет вызван).
- Закрепляет тикет за сотрудником в БД.
- Переводит сотрудника в режим «Фокус на тикете #105».
## 2.3. Сценарий: Режим «Фокуса» (Диалог)

Это основное состояние работы. Все, что пишет сотрудник, улетает конкретному клиенту.

### Интерфейс «Фокуса»

**Бот:**
```
✅ Работа с тикетом #105
Клиент: ООО Ромашка
Введите текст или отправьте файл для клиента.
👇 Управление:
```

**Inline-клавиатура (под сообщением):**
- `[✅ Закрыть]` `[⏳ Ждем клиента]`
- `[🔄 Передать]` `[📁 История]`
- `[❌ Выйти из фокуса]`

### Действия в фокусе:

**Текстовый ответ:**
- **Сотрудник:** "Добрый день, формирую!"
- **Бот (Клиенту):** "Маркова Виктория: Добрый день, формирую!"

**Отправка файлов:**
- **Сотрудник:** Кидает PDF или скриншот.
- **Бот (Клиенту):** Пересылает документ с подписью. (Файл сохраняется в лог тикета).

**Просмотр истории:**
- **Сотрудник** жмет `[📁 История]`.
- **Бот:** Пересылает последние 5 сообщений этого диалога (чтобы вспомнить контекст).
## 2.4. Сценарий: Управление статусами и Навигация

### 1. Переключение между клиентами (Мультизадачность)

**Ситуация:** Сотрудник пишет ответ клиенту А (#105), а в это время пишет клиент Б (#102).

**Бот:** Не прерывает диалог, а шлет тихое уведомление сверху:
```
⚠️ Новое сообщение в тикете #102!
```

**Действие:**
1. Сотрудник жмет `[❌ Выйти из фокуса]`.
2. **Бот:** «Вы вышли в главное меню».
3. Сотрудник жмет `[📥 Активные тикеты]`.
4. **Бот** показывает список:
   ```
   🟢 #105 Ромашка
   🔴 #102 Петров (1 сообщ.)
   ```
5. Сотрудник выбирает #102 и попадает в фокус к нему.

### 2. Статус «Ожидание клиента»

**Ситуация:** Менеджер задал вопрос и не хочет, чтобы тикет висел как «неотвеченный».

**Действие:** Жмет `[⏳ Ждем клиента]`.

**Логика:** Тикет скрывается из горящего списка. Как только клиент ответит — тикет снова станет активным и придет уведомление.

### 3. Передача тикета (Трансфер)

**Ситуация:** Вопрос технический, менеджер не знает ответа.

**Действие:** Жмет `[🔄 Передать]`.

**Бот:** «Кому передать тикет #105?»
- `[Отдел Техподдержки]`
- `[Менеджеру Смирновой]`

**Результат:** Тикет исчезает у текущего сотрудника и появляется как «Новый» у получателя. Клиент видит: «Ваш вопрос передан специалисту».

### 4. Закрытие обращения

**Действие:** Жмет `[✅ Закрыть]`.

**Бот:** «Введите финальный комментарий (или нажмите Пропустить).»

**Сотрудник:** "Счет отправлен".

**Бот (Клиенту):** «Ваше обращение #105 закрыто. Если появятся вопросы — пишите!»

**Бот (Логика):** Отправляет отчет `ticket_closed` в 1С.
