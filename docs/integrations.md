# Интеграции

## MAX

MAX является основным поддерживаемым каналом. События принимаются webhook-маршрутом FastAPI, обработчики находятся в `bots/max_bot/handlers/`, payload-классы — в `bots/max_bot/payloads.py`.

Callback подтверждается через общий безопасный helper. Прикладной handler не должен повторно вызывать подтверждение одного события: MAX отклоняет повторное редактирование или ответ ошибкой `error.edit.invalid.message`.

### Медиа

Перед отправкой медиафайл загружается через `POST /uploads`, после чего полученный token передаётся во вложении `POST /messages`. Один token соответствует одному файлу.

Используемые типы MAX:

| Содержимое | Тип вложения |
|---|---|
| изображение | `image` |
| видео | `video` |
| аудио и голосовое | `audio` |
| документ и другой файл | `file` |
| кнопки | `inline_keyboard` |

Тип `photo` не используется. Для изображения допустим прямой URL; для остальных медиа требуется token загрузки. Действующие ограничения форматов, размеров и комбинаций проверяются по [официальной документации MAX](https://dev.max.ru/docs-api#%D0%9E%D1%82%D0%BF%D1%80%D0%B0%D0%B2%D0%BA%D0%B0%20%D0%BC%D0%B5%D0%B4%D0%B8%D0%B0%D1%84%D0%B0%D0%B9%D0%BB%D0%BE%D0%B2).

Сохранённые вложения нельзя повторно классифицировать только по расширению URL. При пересылке используются сохранённые `MessageType`, имя файла и метаданные `File_Attachment`.

## i-TAT API

Параметры подключения:

- `ITAT_API_BASE_URL`;
- `ITAT_API_USERNAME`;
- `ITAT_API_PASSWORD`;
- `USE_MOCK_ITAT_API`.

Production получает доступ к внутреннему API через корпоративную сеть. Локально можно использовать мок без VPN или реальный API через VPN и SSH/SOCKS5 tunnel, описанный в [README](../README.md#i-tat-api-vpn-и-ssh-tunnel).

Таймаут, временная сетевая ошибка и временный конфликт версии не должны отменять основную операцию бота. Поддерживаемые операции сохраняются в `API_Retry_Queue` и повторяются Celery каждые 5 минут. Успешным считается только явно успешный ответ i-TAT; непустой JSON со статусом ошибки успехом не считается.

`ENABLE_API_RETRY_DIAGNOSTICS=False` обязателен для production. При `True` диагностическое уведомление может содержать URL и payload запроса и предназначено только для кратковременной технической диагностики.

## Входящие webhooks

API приложения подключён с префиксом `/bot/api`. Фактический список маршрутов и схем нужно проверять в `api/__init__.py` и OpenAPI запущенного приложения.

Входящие CRM/i-TAT webhooks используют `WEBHOOK_API_KEY`, передаваемый в заголовке `X-API-Key`. Обработчики покрывают регистрацию, обновление пользователя и сотрудника, назначение менеджера, подписки, статусы и переназначение заявок, конфликты ключей, NPS и рассылки.

Webhook должен быть идемпотентным: повторная доставка одного внешнего события не должна создавать дублирующие сущности или уведомления.
