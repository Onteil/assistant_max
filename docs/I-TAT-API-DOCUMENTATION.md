# I-TAT API Documentation

## Базовая информация

**Base URL:** `http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/`

**Авторизация:** HTTP Basic Auth
- Логин: `dispatcher`
- Пароль: (запросить у администратора)

**Справка:** [http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/getinfo](http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/getinfo)

**Примечание:** Все методы регистронезависимы.

---

## Методы API

### 1. GET /getinfo

Возвращает справку по сервису — описание методов и параметров.

**Endpoint:** `/getinfo`

**Метод:** `GET`

**Пример запроса:**
```
GET http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/getinfo/
```

**Ответ:** Текстовое описание всех доступных методов API.

---

### 2. GET /system/staff

Возвращает список активных сотрудников с учетными записями в мессенджерах.

**Endpoint:** `/system/staff`

**Метод:** `GET`

**Пример запроса:**
```
GET http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/system/staff/
```

**Ответ (успешный):**
```json
{
  "status": "ok",
  "staff": [
    {
      "user_id": 123456789,
      "name": "Иванов Иван Иванович",
      "role": "manager",
      "position": "Менеджер отдела продаж"
    }
  ]
}
```

**Поля объекта сотрудника:**
- `user_id` (number) - идентификатор пользователя в Telegram
- `name` (string) - имя пользователя (наименование из справочника Пользователи)
- `role` (string) - роль пользователя (строковое представление перечисления)
- `position` (string) - должность для подписи

**Ошибки:**
- `500` - внутренняя ошибка сервера

---

### 3. POST /user/register

Регистрирует нового пользователя в системе.

**Endpoint:** `/user/register`

**Метод:** `POST`

**Принимает JSON с полями:**
- `telegram_id` (number, обязательное) - идентификатор пользователя в Telegram
- `phone` (string, обязательное) - номер телефона
- `first_name` (string, опциональное) - имя пользователя
- `last_name` (string, опциональное) - фамилия пользователя
- `grand_key` (string, обязательное) - ключ защиты

**Пример запроса:**
```
POST http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/user/register/
```

**Пример тела запроса:**
```json
{
  "telegram_id": 123456789,
  "phone": "+79001234567",
  "first_name": "Иван",
  "last_name": "Иванов",
  "grand_key": "00202_12345"
}
```

**Ответ (успешный):**
```json
{
  "status": "ok",
  "message": "Пользователь зарегистрирован",
  "user_id": "USER_ID",
  "potential_matches": 0
}
```

**Поля ответа:**
- `status` (string) - статус операции
- `message` (string) - текстовое сообщение
- `user_id` (string) - идентификатор зарегистрированного пользователя
- `potential_matches` (number, опциональное) - количество потенциальных совпадений по телефону

**Ошибки:**
- `400` - неверные параметры запроса
- `404` - ключ не найден
- `409` - пользователь уже существует
- `500` - внутренняя ошибка сервера

---

### 4. GET /user/assets

Возвращает список активов пользователя (организации и ключи защиты).

**Endpoint:** `/user/assets`

**Метод:** `GET`

**Принимает параметры запроса:**
- `telegram_id` (number, обязательное) - идентификатор пользователя в Telegram

**Пример запроса:**
```
GET http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/user/assets/?telegram_id=123456789
```

**Ответ при успехе (пользователь верифицирован):**
```json
{
  "status": "ok",
  "organizations": [
    {
      "inn": "1234567890",
      "name": "ООО Рога и Копыта"
    }
  ],
  "keys": ["MG123456", "MG789012"]
}
```

**Ответ при ошибке (пользователь не верифицирован):**
```json
{
  "status": "error",
  "message": "Пользователь не верифицирован",
  "verification_status": "pending"
}
```

**Ошибки:**
- `400` - неверные параметры запроса
- `404` - пользователь не найден
- `500` - внутренняя ошибка сервера

### 5. POST /tickets/log

Регистрирует обращение пользователя в периодическом регистре сведений.

**Endpoint:** `/tickets/log`

**Метод:** `POST`

**Принимает JSON с полями:**
- `ticket_id` (string, обязательное) - идентификатор обращения
- `telegram_id` (number, обязательное) - идентификатор пользователя в Telegram
- `type` (string, обязательное) - тип обращения (значение из перечисления ай_ТипОбращения)
- `status` (string, обязательное) - статус обращения (значение из перечисления ай_СтатусыОбращений)
- `history_link` (string, опциональное) - ссылка на историю чата
- `comment` (string, опциональное) - комментарий сотрудника

**Пример запроса:**
```
POST http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/tickets/log/
```

**Пример тела запроса:**
```json
{
  "ticket_id": "TG_12345",
  "telegram_id": 123456789,
  "type": "Техподдержка",
  "status": "Новое",
  "history_link": "https://t.me/c/123/456",
  "comment": "Клиент запросил помощь"
}
```

**Ответ (успешный):**
```json
{
  "status": "ok",
  "message": "Обращение зарегистрировано",
  "ticket_id": "TG_12345"
}
```

**Примечание:** При статусе "Закрыто" автоматически проставляется дата закрытия обращения.

**Ошибки:**
- `400` - неверные параметры или недопустимые значения type/status
- `404` - пользователь не найден
- `500` - внутренняя ошибка сервера

### 6. POST /assets/check_key

Проверяет, доступен ли ключ защиты для использования или занят другим клиентом.

**Endpoint:** `/assets/check_key`

**Метод:** `POST`

**Принимает JSON с полями:**
- `grand_key` (string, обязательное) - номер ключа защиты
- `telegram_id` (number, обязательное) - идентификатор пользователя Telegram

**Пример запроса:**
```
POST http://i1.i-tat.ru:33080/sa-001-itatka/hs/dispatcher/v1/assets/check_key/
```

**Пример тела запроса:**
```json
{
  "grand_key": "MG123456",
  "telegram_id": 123456789
}
```

**Ответ при доступном ключе:**
```json
{
  "status": "available"
}
```

**Ответ при конфликте (ключ занят):**
```json
{
  "status": "conflict",
  "owner": "Иван Иванов +7912-XXX-XX-89"
}
```

**Примечание:** Телефон маскируется, оставляя первые 4 и последние 2 цифры. Ключ считается доступным, если он свободен или уже принадлежит текущему пользователю.

**Ошибки:**
- `400` - неверные параметры запроса
- `500` - внутренняя ошибка сервера
